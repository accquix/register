---
title: Search
description: GET /v1/search for autocomplete by name or identifier, and the explicit fuzzy mode.
---

```http
GET /v1/search?q=<text>&mode=default|fuzzy&limit=<1-20>
```

| Parameter | Default | Meaning |
| --- | --- | --- |
| `q` | required | A name or an identifier, 1–200 characters. |
| `mode` | `default` | `fuzzy` corrects typos; it is explicit, rate-limited and may be disabled. |
| `limit` | `10` | At most 20. |

## The result card

| Field | Meaning |
| --- | --- |
| `ico` | The subject's IČO (absent for a record without one). |
| `name` | The display name, with diacritics and legal form. |
| `matchedName` | The official name that matched, when it is not the display name (a sole trader's other name). |
| `municipality` | Municipality of the seat or place of business. |
| `kind` | `legal_person`, `sole_trader`, `public_body` or `other`. |
| `active` | `false` only for a terminated subject found by identifier. |
| `typos` | Fuzzy only: corrections needed. |

Search proposes; it does not resolve. When the user picks a card, call
[`GET /v1/lookup/{ico}`](/api/lookup) for the full record.

## Good client behaviour

- **Debounce typing** by about 120–250 ms. Without it, every keystroke is a request.
- **Never auto-select the first result.** Two subjects can share a name.
- **Offer fuzzy only as an explicit action**, for example "Nothing found. Search with typos?", and only when
  [`/v1/capabilities`](/reference) says it is enabled.
- On `429`, wait the number of seconds in `Retry-After`.
