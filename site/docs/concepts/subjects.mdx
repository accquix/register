## One subject, several registrations

In RPO, one IČO can have **several records**: a sole trader has one per source register (for example the Trade
Register and the register of financial agents), and an old company can have closed branch records. About 22 600
IČOs have more than one active record.

Accquix Register treats them as **one subject**:

- the lookup returns `identity.registrations[]`, one entry per record, each with its register, office, number,
  the name in that record, and whether it is active;
- the **display name** comes from the Commercial Register or Trade Register record, else from the most recently
  changed record;
- **every official name is searchable**, so a sole trader is found under any of the names they use;
- a record without a valid IČO keeps its own identity, keyed by its RPO id.

## Identifiers are matched exactly

| Typed | Recognised as | Example |
| --- | --- | --- |
| 8 digits | IČO | `99900001` |
| 10 digits | DIČ | `2099900001` |
| `SK` + 10 digits | IČ DPH | `SK2099900001` |

Spaces are ignored and `sk` is accepted. Identifiers are **never matched fuzzily**: an IČO that differs by one digit
is another, real company.

:::warning[The IČO check digit is a warning only]
The last digit of an IČO is a mod-11 check digit. In the real data, 778 IČOs fail it, 16 of them active.
So a failing IČO is never rejected: when it exists in RPO it is returned, and `identity.icoChecksumValid` says
`false`.
:::

**An IČ DPH is not a unique key.** The members of a VAT group (§4b) share one IČ DPH, so a lookup by IČ DPH can
return several subjects.

## Every case of IČO and DIČ

What the register does in each case, with taxpayers off (the default) and on (`REGISTER_SEARCH_TAXPAYERS=true`).
Exact lookup by IČO, DIČ or IČ DPH is the same in both.

| Case | Name search, off | Name search, on | Exact IČO or DIČ |
| --- | --- | --- | --- |
| IČO and DIČ (a company, a sole trader) | found | found, as when off | the subject, with every section |
| IČO, no DIČ yet (a new business) | found from RPO | the same | IČO finds it, tax section `absent`; counted as `itemsWithoutDic` in `/v1/sources` |
| DIČ only (a private person, such as a landlord) | not found | by the full name only: DIČ, name, municipality, published address; at most five, after the businesses | DIČ gives a `taxpayer`: name, municipality and the published address |
| DIČ only, with a malformed IČO in the DIČ list | not found | as "DIČ only" | as "DIČ only" |
| Neither IČO nor DIČ | the item is left out and counted (`skippedItems`); above the list's cap the list is blocked | the same | — |
| DIČ only, then an IČO appears | found as a business | leaves the taxpayer search, found as a business | both lead to the business |
| IČO first, the DIČ later | found | the same | the DIČ starts leading to the business |
| Objection by IČO | its records are hidden | hidden, and so are DIČ-only rows whose full name the subject's name holds (namesakes too) | still found |
| Objection by DIČ (a private person) | changes nothing: not in name search anyway | out of the taxpayer search | still found |
| Objection by DIČ, then an IČO appears | the records with that IČO are linked and hidden by themselves | the same | still found |
| Objection by DIČ, the IČO appears and goes again | the link stays, the records stay hidden | the same | still found |
| Anonymous access on | DIČ-only rows are never shown, not even by exact DIČ | taxpayers cannot be on with anonymous access | IČO and businesses only |
| Fuzzy search (`mode=fuzzy`) | businesses only | taxpayers are not searched (`not_searched`) | — |
| The DIČ list is stale | — | taxpayers are not searched (`stale`); never "not found" | a DIČ answers `503` or carries `stale` |
| Over the taxpayer limit | — | businesses are found, taxpayers not (`rate_limited`) | not affected |

An objection by DIČ for a DIČ that already has an IČO is refused: object by the IČO.

## What the source data looks like

These facts, found in the real files, shape how the register reads them:

- about 6 600 RPO records carry a text placeholder instead of an IČO; they are treated as having no IČO;
- some IČOs in the Financial Administration lists are not 8 digits (mostly 12-digit numbers of another kind);
- RPO writes the PSČ both as `83237` and `811 06`; the register returns `NNN NN`;
- when a subject is terminated, RPO closes every attribute; the register then shows the last valid value;
- the special VAT scheme list can have several periods with the same start date for one subject.
