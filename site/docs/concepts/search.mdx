There is one search box. An identifier is looked up exactly; anything else is a name search over the active
subjects. Names are compared without diacritics, without case and without the legal form, so
`Zlatá Rybka, s.r.o.`, `zlata rybka` and `ZLATÁ RYBKA a.s.` are the same words.

| | Search `GET /v1/search` | Lookup `GET /v1/lookup/{id}` |
| --- | --- | --- |
| Input | a name, or an exact IČO, DIČ or IČ DPH | an exact IČO, DIČ or IČ DPH |
| Answer | up to 20 candidates: name, identifiers, address, kind, active | one subject with every section: identity, tax, VAT, risk, each with its source and date |
| Terminated subjects | by identifier only, flagged `active: false` | yes |
| Taxpayers without an IČO | by exact DIČ; by full name only when the operator turns it on: DIČ, name, municipality | by exact DIČ only: DIČ, name, municipality |
| Subjects with an objection | by identifier only | yes |
| Use it to | let a person pick a business | confirm facts before you rely on them |

## Default search

The default search answers as you type. It runs two steps:

1. **Name prefix**: names that start with the query. `zlata ryb` finds `Zlatá Rybka, s.r.o.`.
2. **Word prefixes**: every word of the query must be the start of a word of the name, in any order.
   `rybka zlata` and `ryb` find it too.

The second step runs when the first one returned fewer than 10 results, or when the rarest query word is rare
enough to be cheap. It is driven by the rarest word and capped, so a very common word (`obec`, `slovenska`) does not
make the query expensive.

**Ranking:** an exact name first, then names that contain all query words as whole words, then names that start with
the query, then shorter names. There is no popularity signal in the data, so the register does not invent one.

## Fuzzy search (optional)

`mode=fuzzy` corrects typos. It is **never automatic**: call it when the default search found nothing and the user
asks for it, for example with a "Search with typos?" button.

<Steps>
  <Step title="Keep known words">
    Query words that are the start of a known word stay as typed.
  </Step>
  <Step title="Correct unknown words">
    Each unknown word is compared with the dictionary of all words in the register: first by trigrams, then by edit
    distance with adjacent transpositions. `sporitelan` → `sporitelna` is one transposition. A word of up to four
    letters may have one typo, a longer word two; a short word is checked against every word one edit away, since
    it has too few trigrams for the first step.
  </Step>
  <Step title="Search with the corrections">
    The corrected words go through the default word search. The response lists the corrections.
  </Step>
</Steps>

Fuzzy search is **optional and potentially CPU-intensive**, and it **never substitutes exact identifier matching**.
Operators can switch it off (`REGISTER_SEARCH_FUZZY=false`); `/v1/capabilities` tells clients whether it is on. It
has a limit on concurrent fuzzy searches, a timeout and, when the operator sets one, a rate limit per key.

## Taxpayers without an IČO

About 159 000 taxpayers in the Financial Administration's DIČ list have no IČO: mostly private persons, for example
landlords. By default they are found only by their exact DIČ. An operator can turn on name search for them
(`REGISTER_SEARCH_TAXPAYERS=true`); it is deliberately narrower than the search for businesses:

- **The full name only.** Every word of the name and no other, in any order: `Jana Fiktívna` and `fiktivna jana`
  find "Jana Fiktívna", but `jana`, `jana fikt` and `jana fiktivna nova` do not. Diacritics and case are ignored.
- **Default mode only**, never fuzzy, and only with an API key; never on an instance with anonymous access.
- **What the lookup gives:** DIČ, name, municipality and the address as the DIČ list publishes it. Cards have `kind: taxpayer` and come after the businesses, in the
  room they leave, at most five. See [Data and privacy](/project/data-and-privacy#taxpayers-without-an-ičo) before
  you turn it on.
- **Its own limit** per key (1 a second, burst 10: enough for a person typing a name, slow for harvesting). Over
  it, the search still answers, without taxpayers, and the response says `taxpayers: rate_limited`. With one key
  for a whole application, all its users share this limit: raise it for a busy application.
- **Only from a fresh DIČ list.** When it is stale, taxpayers are not searched (`taxpayers: stale`), so a missing
  person never looks like a confirmed absence.
- **Objections:** a person can object by DIČ (`suppress --subject <DIČ>`); the register then never returns them in
  name search, and if the DIČ list later gives them an IČO, their business records are hidden too, automatically.
  An objection by IČO also covers a DIČ row that may be the same person: when an objected subject's name holds the
  queried full name as adjacent words, no taxpayer is returned for it, namesakes included. Both checks run on every
  query.

The response field `taxpayers` says what happened: `searched`, `not_searched` (fuzzy mode, fewer than two words, or
the businesses filled the limit), `rate_limited` or `stale`. It is absent when the switch is off.

## What it costs

Measured on the real data (1 017 893 active subjects) on a small database:

| | Default search | Fuzzy search |
| --- | --- | --- |
| Typical | 1–5 ms | 3–5 ms |
| Worst queries, full machine | under 10 ms | about 60 ms |
| Worst queries, 1/8 vCPU database | about 50 ms | hundreds of ms |

When the database is saturated, a 1/8 vCPU tier answers about 30 default searches a second and a 1/4 vCPU tier
75–140. With a client debounce of about 120 ms, a person typing sends one to three searches a second.

## What search does not do

- Terminated subjects are not in name search. An exact identifier finds them, flagged `active: false`.
- Natural persons without an IČO (taxpayers known only by DIČ) are not found by name unless the operator turns it
  on, and then only by the full name ([above](#taxpayers-without-an-ičo)). Their exact DIČ typed into the box gives
  one card of `kind: taxpayer`, the same as the lookup (with the published address), and not on an instance with
  anonymous access.
- A subject kept out of search after an objection is still found by its exact identifier.
- Results are capped at 20; there is no paging in v1.
- Inflected forms are different words: `lipa` does not find "U Lipy". Type the start of the word (`lip`), or use
  fuzzy search for one changed letter.
